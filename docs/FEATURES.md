# 增强功能说明

本仓库在官方 vertex 的基础上新增了以下功能。

## 1. 顺序下载 (下载器配置)

添加种子时向 qBittorrent 传递顺序下载开关, 同 qBittorrent 右键菜单 - 顺序下载。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sequentialDownload` | boolean | 开启顺序下载 |

## 2. 自动校验 (下载器配置)

定时扫描下载器内体积相同的种子, 若最快与最慢进度差超过阈值,
对进度落后的种子执行重新汇报 + 强制重新校验 (recheck)。
上传速度达到保护值、属于排除分类、或正在校验/移动中的种子不参与。
日志输出在 `logs/app-sc.log`。

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `autoRecheck` | boolean | false | 开启自动校验任务 |
| `recheckCron` | string (cron) | `*/3 * * * *` | 任务执行周期 |
| `categoryList` | string[] | `['keep']` | 排除的分类列表 |
| `minProgressDifference` | number (0~1) | 0.05 | 触发校验的最小进度差 |
| `minUploadProtection` | number (byte/s) | 52428800 | 上传速度保护阈值, 达到则不校验 |

注意: 自动校验没有可视化表单, 新增下载器时以上默认值会随表单一同保存,
如需开启或调整, 编辑下载器配置数据即可。

## 3. RSS 首选下载器调整 (RSS 任务配置)

开启后优先将种子推送到已存在同体积种子的下载器, 忽略原有的首选下载器逻辑。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `adjustFirstClient` | boolean | 开启首选下载器自动调整 |

## 4. RSS 仅辅种 (RSS 任务配置, 需先开启首选下载器调整)

开启后 RSS 只做辅种, 永远不会普通下载。对每个 RSS 种子扫描所有可用下载器中的
同体积种子 (优先已完成的, 其次进度最高的), 三段式判定:

- 本地已完成 → 立即辅种 (校验 bencode 文件名一致后, 以本地种子的保存路径添加)
- 进度达到"等待进度"但未完成 → 进入**等待辅种队列**, 完成后自动辅入
- 低于"等待进度" / 文件名不匹配 / 无同体积种子 → 拒绝并写入历史记录

辅种成功时自动打标签 (仅 qBittorrent): 辅入的种子打 `辅种`, 本地来源种子打 `辅种源`,
方便在下载器里区分, 也可用于删种规则/自动校验的排除条件。

等待辅种队列:

- 全局队列, 每 10 秒检查一次, 存储于 `data/reseed-queue.json`, 重启不丢失
- 每轮检查会重新扫描该任务的全部下载器, 任何下载器中的匹配种子先完成就辅到哪
- 出队条件: 辅种成功 / 等待超时 / 本地种子已删除 / 下载器中已存在该种子 / 手动放弃
- **删种保护**: 正在被等待辅种的本地种子, 删种规则会自动跳过, 避免等待落空
- 等待中的种子在 **任务历史 - 等待辅种** 页面查看 (实时进度、剩余等待时间), 可手动放弃
- 页面顶部显示辅种统计 (成功/超时/放弃/平均等待时长, 存储于 `data/reseed-stats.json`),
  可据此调整"等待进度"与超时参数; 统计保留天数在 设置-基础设置 中自定义
  (`reseedStatsDays`, 默认 7 天)
- 所有事件写入 `logs/app-watch.log`, 终态写入 RSS 历史记录

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `auxiliaryTorrent` | boolean | 开启仅辅种模式 |
| `auxiliaryProgress` | number (0~1) | 等待进度: 达到此值等待完成后辅种, 低于直接拒绝, 默认 0.8 |
| `auxiliaryTimeout` | number (分钟) | 等待超时, 默认 15 |
| `autoReseed` | boolean | 跳校验: 勾选立即做种; 不勾选以本地路径添加, 由下载器自动校验后做种 |

## 5. 下载器停用与 RSS 任务下载器的约束放宽

官方版中, 被 RSS 任务引用的下载器无法停用, RSS 任务又必须至少选择一个下载器,
单下载器任务与下载器互相锁死。本版本改为:

- **被引用的下载器可以直接停用**: 点击停用时弹出确认框, 列出引用它的 RSS 任务。
  任务中的引用原样保留, 停用期间该下载器视作不可用, 重新启用后自动恢复,
  任务配置全程不被修改。删除下载器时的占用检查保留不变
- **任务的下载器全部不可用时整轮跳过**: 记一条日志, 不写拒绝记录,
  下载器恢复后 RSS 自动继续 (官方版的行为是逐种子写"无可用下载器"拒绝记录,
  这些种子之后永远不会再被处理)
- **等待辅种队列**把"下载器已停用"与"暂时离线"同样处理: 继续等待, 超时兜底
- **RSS 任务允许不选下载器**: 保存时任务自动停用并提示;
  未选下载器的任务无法启用 (前后端均拦截)。由此也解开了删除下载器的死锁:
  编辑任务移除该下载器 (任务自动停用) → 删除下载器 → 之后重新配置再启用

注意: 切换回官方版前, 请确保**已启用**的任务至少有一个已启用的下载器
(或先停用任务), 否则官方版运行时会给当轮 RSS 内所有种子写入拒绝记录。

## 6. HZC 自动重建 (任务配置 - HZC自动重建)

Hetzner Cloud 服务器流量轮换: 出站流量或机龄达到阈值时自动删除服务器并从快照重建
(重新获得流量配额), 重建后自动把 VT 下载器地址切到新 IP。

- 按**受管服务器名称列表**识别机器, 账号内其他服务器完全不受影响;
  数量不足目标值时按列表顺序自动补建
- 重建条件: 流量阈值 (TiB) 与机龄上限 (天) 均可留空 (留空不启用该条件);
  两者都留空时任务退化为纯监控 + 自动补建
- 创建策略列表: (型号, 快照 ID) 从上到下依次尝试, 应对型号缺货;
  全部失败自动重试, 最终失败发通知并等下轮自动补齐
- 重建后默认轮询新服务器服务端口, 就绪后再切换下载器地址 (超时可配, 0 为不等待)
- 通知走 vertex 通知工具, 摘要报告与重建事件可分别多选通知渠道;
  摘要报告有独立的 Crontab 周期, 留空不发送
- 新增 **PushPlus** 通知类型 (通知工具 - 类型 - PushPlus, 填用户 Token 即可)
- 页面提供服务器状态看板 (流量进度条/运行时间/关联下载器上传量,
  数据来自每轮检查后的缓存, 可手动刷新) 与近 30 天重建统计
- API Token 仅存于 `/vertex/data/hzc/`, 列表接口返回掩码, 表单留空表示不修改
- 防重入: 检查周期与重建流程互斥, 手动"立即执行"同样受锁保护

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `checkCron` | string (cron) | `*/15 * * * *` | 检查周期 |
| `reportCron` | string (cron) | 空 | 摘要报告周期, 留空不发送 |
| `serverNames` | string[] | - | 受管服务器名称, 如 `["box-1", "box-2"]` |
| `desiredCount` | number | 1 | 维持的服务器数量 |
| `trafficLimit` | number (TiB) | 17 | 流量阈值, Hetzner 免费额度 20TB ≈ 18.19TiB |
| `maxAgeDays` | number (天) | 空 | 机龄上限 |
| `rebuildWait` | number (秒) | 120 | 删除后到重建的等待 |
| `readyTimeout` | number (分钟) | 10 | 新机就绪等待上限, 0 不等待 |
| `strategies` | {serverType, snapshotId}[] | - | 创建策略, 型号全小写, 如 `cx43` / `123456` |
| `updateClient` | boolean | true | 重建后自动更新 VT 下载器地址 |

## 7. 其他

- qBittorrent 客户端新增 `removeTags` (删除种子标签)、`recheck` (重新校验) 接口封装
- `lemon` 站点移出 RSS 长缓存名单 (恢复默认 40 秒缓存)
- 新装实例默认主题为 follow, 仪表盘默认仅显示下载器与 Tracker,
  默认隐藏订阅/豆瓣/链接工具等与刷流无关的菜单 (见 `app/config/setting.json`,
  可在 设置-菜单设置 中随时改回)

## 与官方版切换的注意事项

- 备份/还原与官方版互通: 本版本不修改数据库表结构, 新增状态均存于
  `/vertex/data` 下的 JSON 文件, 官方版恢复本版本的备份时会忽略多余文件, 无害
- 但在**官方版里编辑并保存**某个 RSS 任务/下载器后, 其中的增强字段会被官方版
  的保存逻辑抹掉, 切回本版本后需要重新勾选相关选项
